## 0. 一句话结论

作为「专项刷题 + 错题复盘」工具，这个程序基本可用：题库结构与官方一致，填空题判分与官方接受表逐条吻合，做题时不泄露答案。

但**「全真模考」这一块与官方 Bluebook 差距最大**：没有模块、没有休息、没有自适应，计时器可漂移、可在恢复会话时重置，时间到后还能继续改答案并交卷。也就是说，模考报出来的数字**不能当作真考水平**。此外还有一批与官方无关、但确实存在的程序 bug（个人单项入口不可用、未作答被算成错题、假掌握度 75%、快捷键没实现等）。

### F1【高】“全真模考”并不全真：无模块、无休息、无自适应

**程序现状**

- 模考页明确写着：
  - “两阶段自适应路由，完整 54 题 R&W + 44 题 Math，支持休息与断点防丢失。”（`index.html:317`）
  - “2 个 Section 共 4 个 Module，中间含 10 分钟中场休息。”（`index.html:324`）
- 实际 `startMock()`（`index.html:2168-2211`）只做了一件事：随机抽 54 道 R&W + 44 道 Math，放进**一个** `initRunnerSession`，给一个 64/70/134 分钟的连续倒计时。
- 代码里没有 module 边界、没有 break、没有“Module 2 按 Module 1 表现换难度”的路由；除了上面两句文案，搜不到任何模块/休息/路由逻辑。
- 标题还写“SAT 完整全真模考 (自适应)”（`index.html:2191`），但抽题是 `Math.random()` 随机（`index.html:2188-2199`）。

**官方要求**：O2、O3。两个 section 各两个**分别计时**的 module；时间到自动进入下一模块；两节之间有短休息；Module 2 是自适应路由。

**影响**：用户以为在模拟真考节奏，实际是“98 道混合套题”。跨 module 回看做题、R&W 与 Math 之间自由往返、没有休息，这些都会让模考体验和分数参考价值偏离真考。

**建议**：要么真做 4 个 module + 休息 + 路由，要么把文案改成“完整套题练习（非全真）”，不要同时保留“4 Module / 10 分钟休息 / 自适应”的宣称。README 的“已知缺口”已经承认难度自适应没做，但页面文案仍在承诺，这是最容易误导的一条。

### F2【高】时间到不锁卷、不自动提交，仍可改答案并手动交卷

**程序现状**

- 倒计时归零时（`index.html:2415-2419`）：`clearInterval` → `alert("答题时间已到...")` → `openReviewScreen()`。
- 检查页的“返回做题”按钮（`index.html:572`）直接 `switchView('runner')`，没有任何“已超时”的锁。
- 实测（jsdom）：时间到后回到答题界面，`selectOption("A")` 仍能写入；接着 `confirmSubmitModule()` 仍照常记录并结算。
- 检查页只有一行“当前有 N 题未作答”的提示（`index.html:2855`），没有阻止交卷。

**官方要求**：O2。时间到模块结束，Bluebook 自动推进/提交，作答锁定。

**影响**：这是模考分数虚高的直接入口——时间到了还能慢慢改，计时压力等于不存在。

**建议**：归零时设置 `locked=true`，冻结选项/填空/导航，直接进入“已提交”状态或只读检查页；`confirmSubmitModule` 拒绝重复提交。

### F3【高】计时器按 tick 递减，不是墙钟；后台/卡顿会漂移

**程序现状**

- `setInterval(..., 1000)` 里每次 `timeLeft--`（`index.html:2409-2420`），全程没有用 `Date.now()` 校正剩余时间。
- `endTime`、`timerPausedTotal` 两个字段只写不读（`index.html:1835` 之后再无读取）。
- 实测：主线程阻塞 5.1 秒，倒计时只减少 1 秒（`timeLeft 600 → 599`）。
- 浏览器后台标签页会节流 `setInterval`（Chrome 后台可低至 1 次/分钟），效果同上：64 分钟的模考可以跑出几小时。

**官方要求**：Bluebook 的计时是每个 module 的权威倒计时（O2/O4）。

**影响**：模考时间不准；“官方配速”统计失去意义；用户切到别的标签查资料时，等于白送时间。

**建议**：保存 `endTime = Date.now() + limit*1000`；每秒（或每 250ms）用 `remaining = endTime - Date.now()` 渲染；暂停时把 `endTime += pauseGap`；页面 `visibilitychange` 回来时立即重算。

### F4【高】恢复未完成会话时，倒计时重置为满时长

**程序现状**

- `initRunnerSession` 无条件 `timeLeft = session.timeLimitSec`（`index.html:2406`）。
- `timeLeft` 是脚本全局变量，不属于 `activeSession`，所以 `Store.saveSession` 根本存不到它（`index.html:1198`、`2457`）。
- 实测：一场 600 秒的会话做到只剩 120 秒，保存后重新 `initRunnerSession(Store.loadSession())`，`timeLeft` 回到 600。

**官方要求**：真考没有“恢复现场”；但程序自己宣传“断点防丢失”（`index.html:317`），恢复却白送时间。

**影响**：刷新/崩溃/关标签再恢复 = 重新计时。这是 F3 之外第二条“偷时间”路径。

**建议**：持久化 `endTime`（或 `timeLeft` + `startedAt`），恢复时按墙钟算剩余；如果剩余 ≤ 0，直接进入已提交状态。

### F7【中】“官方公式表”严重不全

**程序现状**（`index.html:811-816`）只有 4 项：

- 圆：`A = πr², C = 2πr`
- 三角形：`A = ½bh, a² + b² = c²`
- 体积：`V = lwh, V = πr²h`
- 特殊角：`30°-60°-90°: x, x√3, 2x`

**官方公式表**（O7 第 8 页 / O8 第 32 页）还包括：

- 矩形 `A = ℓw`
- 45°-45°-90°：`x, x, x√2`
- 球 `V = 4/3 πr³`
- 圆锥 `V = 1/3 πr²h`
- 棱锥 `V = 1/3 ℓwh`
- 圆 360°、`2π` 弧度、三角形内角和 180°

**影响**：学生点开“官方公式表”以为就这些，考试时容易漏公式。

**建议**：按官方第 8 页整表替换；中文标签可以保留，但内容不要删。

### F8【中】SPR 输入没有即时校验、没有预览、没有规则说明

**程序现状**

- 输入框（`index.html:489-492`）没有 `maxlength`、没有 `pattern`；`handleSprInput` 只做 `v.trim()` 后存值（`index.html:2556-2558`）。
- 字符/长度/禁用符号的校验只在交卷判分时由 `sprFormat` 执行（`index.html:2226-2237`），用户输入过程中没有任何反馈。
- 实测：输入框 `maxlength` 为空、`pattern` 为空；可以输入 `1,000`、`abc`、`0.1764`，交卷时静默判 0。

**官方要求**：O5。Bluebook 在输入时就会阻止超长数字和非法字符，并预览作答；O7 还要求旁边展示 SPR 规则（5/6 字符、不能有逗号/百分号/美元符号、带分数写法）。

**影响**：用户可能因为“能打进去”而以为格式没问题，交卷才发现错；这是可避免的失分。

**建议**：输入框加 `maxlength`（正数 5 / 负数 6，随首字符动态）+ 非法字符拦截 + 实时提示 + 预览；旁边放一段官方规则摘要。

> 注：**判分本身是对的**。见第 4 节，`sprMatch` 与官方接受表逐条吻合，不要把这条误读成判分 bug。

## 3. 程序自身 bug（与 Bluebook 无关，但真实存在）

### B1【高】未做题的技能默认显示 75% 掌握度；首页五个进度条是写死的

**证据**

- `index.html:1414`：`const skAcc = skAttempts.length ? ... : 75;` —— 没做过任何题的技能也显示“掌握度: 75%”，并画出 75% 的进度条。
- 首页五个分类进度条宽度写死在 HTML：`15% / 25% / 20% / 30% / 10%`（`index.html:149,168,187,206,225`），JS 从未更新。
- 实测：`attempts=[]` 时渲染词汇专项，卡片文案包含“掌握度: 75%”；进度条仍是 15/25/20/30/10。

**影响**：与 README “默认状态……统计全是 0”直接矛盾；用户会以为系统已经评估过自己。

**建议**：无记录时显示“— / 未练”，进度条 0%；有记录时按 attempts 实时算。

### B2【高】“个人单项”三张卡是死链

**证据**

- `CATEGORY_MAP.custom.skills` 是“错题集集中突击 / 高频标记题目 / AI推荐靶向题”（`index.html:886-892`）。
- 但 `categorizeQuestion` 永远不会返回 `custom`（`index.html:1295-1304`），所以 `renderCategoryDetail` 里这三张卡都是“0 题”（`index.html:1412`）。
- 点“开始这批专项练习”时 `pool = BANK.filter(q => q.cat === selectedCat)` 得到空数组，直接弹“当前筛选条件下无题目”（`index.html:1468-1479`）。实测确认。
- “高频标记题目”也没有数据来源：`flagged` 只存在当前 session 的 answer 里，交卷即丢；没有持久化的标记表。
- “AI推荐靶向题”没有对应实现（只有 AI 弱点诊断，没有“按 AI 推荐出题”）。

**影响**：整个 05 分类点进去无法使用。

**建议**：三张卡分别接到 `redoAllMistakes()`、持久化标记表、AI 推荐结果；接不了就先移除，别留死入口。

### B3【高】界面宣传的键盘快捷键没有实现

**证据**

- 做题底栏写着“快捷键: [A/B/C/D] 选择 · [Alt+F] 标记 · [Esc] 暂停”（`index.html:524`）。
- 全文件只有一个 `keydown` 监听（`index.html:1784-1794`），只处理 `Escape`。
- 实测：对 document 派发 `keydown key='b'`，`picked` 仍为 `null`；派发 `Alt+F`，`flagged` 仍为 `false`。

**影响**：用户按了没反应，会以为程序卡住。

**建议**：实现 A/B/C/D 与 Alt+F（注意在 SPR 输入框聚焦时不要触发），或删掉这行提示。

### B4【高】未作答也会被记成 attempt + 错题，并打上错因标签

**证据**

- `confirmSubmitModule` 对**每一道题**都 `attempts.push(...)`（`index.html:2870-2904`），未作答时 `picked=null`、`ok=false`。
- 未作答同样进入 `mistakes[q.id]`，`wrong: "未作答"`（`index.html:2906-2927`）。
- 实测：2 道题只答 1 道就交卷，`attempts.length` 变成 2，两道都 `ok=false`，未答的那道也被打上标签。

**影响**：在专项练习里尤其不合理——做 3 题就交卷，剩下 7 题全被算错并进错题本；“已作答”计数虚高，正确率被拉低。模考里未作答按官方确实应计 0 分，但也不该进错题本、更不该打“概念漏洞”标签。

**建议**：只对 `picked !== null && picked !== ""` 的题写 `attempts`；未作答单独记 `answered:false`。模考计分时把未答按 0 分计，但**不进 `mistakes`、不打错因标签**；专项练习则直接不记录未答。交卷前对未答题二次确认。

### B5【中】错因的“快/慢”阈值与四象限阈值不一致；速度标签混进错因分类

**证据**

- `classifyError` 用配速的 0.7 / 1.3 倍判断快慢（`index.html:2331-2335`）：R&W 快于 49.7 秒算“快而错”，慢于 92.3 秒算“慢而错”。
- 报告/复盘的四象限用固定阈值：快 `< 25 秒`，慢 `> 71 秒`（`index.html:1597-1598`、`1910-1911`）。
- 当没有匹配到概念类错因时，`classifyError` 直接把速度标签当错因返回：`tag = speedQuadrant !== "正常配速" ? speedQuadrant : "未归类"`（`index.html:2387`）。

**影响**：同一道题在错题本里的标签可能是“快而错（疑似粗心）”，在复盘页却不属于任何象限；README 承诺的“11 类 / 归不了标未归类”也被速度标签打破。

**建议**：快慢阈值只保留一处；`tag` 只输出概念类或“未归类”，速度单独存 `quadrant`。

### B6【中】导入备份成功后抛 `ReferenceError`（`view` 未定义）

**证据**

- `index.html:1754`：`if (typeof renderReport === "function" && view === "report") renderReport();`
- 全文没有声明 `view`；作用域扫描（acorn）在 3,555 行里只找到这一个未声明标识符。
- 实测：导入合法备份，数据合并成功，但 `window.onerror` 捕获 `ReferenceError: view is not defined`；报告页不会刷新。

**影响**：控制台报错；目前不影响数据落盘，但属于“导入成功却报错”，会让人以为导入失败。

**建议**：改成当前视图判断（例如维护 `currentView` 变量），或直接删掉这个刷新分支。

### B7【中】重点（keypoints）不在备份/云同步范围

**证据**

- `collectBackup()` 只导出 `attempts / mistakes / vocab`（`index.html:1653-1662`）；实测键为 `_format,_version,exportedAt,attempts,mistakes,vocab`。
- `Cloud.rowsFor` 也只有这三张表（`index.html:1035-1056`）。
- 但 `Store.addKeypoint` 把“重点”按 qid 永久存（`index.html:1235-1240`），文案还写“永久跟着这道题”。

**影响**：换设备、清缓存、Safari 驱逐后，重点全部丢失；备份/云同步救不回来。

**建议**：把 keypoints 加进备份与云端表（或在 UI 上明确写“重点只在本机”）。

---

### B8【中】保存失败是静默的：配额写满也不会报错

**证据**

- `Store.put` 捕获异常后只 `console.warn` 并 `return false`（`index.html:1175-1181`），不抛错。
- `confirmSubmitModule` 忽略 `Store.saveAttempts` 的返回值（`index.html:2940`）。
- `importBackup` 的 `try/catch` 包住的是不会抛错的 `saveAttempts`（`index.html:1744-1750`），所以“存储写满”的提示永远不会出现。

**影响**：配额满时，界面说“已合并/已提交”，刷新后数据没了。

**建议**：检查返回值，失败时明确提示并建议先导出；导入后回读校验。

---

### B9【中】高亮的会话数据从不清理

**证据**

- `Store.dropSessionHighlights(sid)` 定义在 `index.html:1227-1231`，但全文件没有任何调用。
- 高亮按 `sid + qid` 存在 localStorage（`index.html:1202-1231`），交卷后只把“哪些题画过”带进复盘，正文键值一直保留。

**影响**：localStorage 只增不减；长期使用会挤占配额（再叠加 B8 的静默失败就更危险）。

**建议**：复盘页打开或关闭时调用 `dropSessionHighlights(sid)`。

---

### B10【中】间隔复习只写不读：盒号/到期日从不展示，重练也不按 due

**证据**

- 交卷时写入 `box / due / lapses`（`index.html:2922-2935`）。
- 全文件没有任何地方用 `due` 做调度或展示（其余出现位置只有写库和云同步行构造）；`renderMistakesView` 只看 `mastered`（`index.html:2980`）；`redoAllMistakes` 也是“所有未掌握”（`index.html:3044`）。
- 实测/静态检查：错误本卡片不显示第几盒、下次该复习哪天。

**影响**：README 宣称的“1 → 3 → 7 → 16 天”机制在数据层存在，但用户看不到、也用不上，等于没生效。

**建议**：错题卡显示“第 N 盒 · 下次复习 X 天/已到期”；首页加“今日该复习”队列；`redoAllMistakes` 默认只取 `due <= now`。

### B11【中】“错因自述”没有输入 UI，`why` 永远为空

**证据**

- `attempts.why` 只会从 `a.why` 读取（`index.html:2900`、`2919`），全文件没有任何地方给 `a.why` 赋值；也没有 `textarea` / `input` 让用户写“我当时怎么想的”。
- README 却把“错因自述：答错后先写一句……”列为核心功能；AI prompt 也写“结合考生自述（如有）”。

**影响**：文档承诺的功能不存在；数学错因基本只能靠自述，这一块等于缺失。

**建议**：在交卷后的复盘页给每道错题加一个“我当时怎么想的”输入框（或做题时答错即弹），保存到 attempt/mistake。

### B12【中】检查页/复盘页的时间被算进当前题

**证据**

- `questionT0` 在每次 `renderRunnerQuestion` 时重置（`index.html:2456`）；`openReviewScreen` 不结算、不暂停（`index.html:2829`）。
- `confirmSubmitModule` 最后把 `Date.now() - questionT0` 加给当前题（`index.html:2860-2865`）。
- 如果在检查页停留 3 分钟再交卷，这 3 分钟会记到“当前题”的用时里。

**影响**：平均用时、四象限（慢而对/慢而错）被污染。

**建议**：进入检查页时先结算并清空 `questionT0`；回到做题时再重新计时。

### B13【低】每点一次选项就序列化整场题目；SPR 输入反而完全不保存

**证据**

- `renderRunnerQuestion` 每次都 `Store.saveSession(activeSession)`（`index.html:2457`）；`selectOption` → `renderRunnerQuestion`（`index.html:2545-2548`）。
- 全真模考一场 98 题，实测 JSON 约 **0.6–1.1 MB**；每点一次选项都写一遍。
- `handleSprInput` 只改内存，不 `saveSession`（`index.html:2556-2558`）：输入填空题后如果刷新/崩溃，答案丢失。

**影响**：模考点选项卡顿、localStorage 压力大；填空题答案反而最容易丢。

**建议**：`saveSession` 去抖（如 500ms）；SPR 输入同样去抖保存；页面试图隐藏时强制保存一次。

### B14【低】样式依赖两个 CDN，断网/CDN 不可达时界面会散

**证据**：`index.html:7-8` 引入 `cdn.tailwindcss.com` 与 `cdnjs.cloudflare.com` 的 Font Awesome；本地样式只定义了很少几个类。

**影响**：题库在本地，但断网或 CDN 被墙时页面基本没有布局、图标全空。与“纯静态、打开就能用”的预期有落差。

**建议**：把 Tailwind 构建产物和 Font Awesome 子集放到本地（或至少把关键 CSS 内联）。

### B16【低】“删除账号”只清空三张表，不删除 auth 用户

## 4. 已核实“没问题”的项（避免误报）

1. **SPR 判分与官方接受表一致**。官方 O7 第 7 页的示例表：答案 2/3 接受 `2/3`、`.6666`、`.6667`、`0.666`、`0.667`，拒绝 `0.66`、`.66`、`0.67`、`.67`；答案 -1/3 接受 `-1/3`、`-.3333`、`-0.333`，拒绝 `-.33`、`-0.33`；答案 3.5 接受 `3.5`、`3.50`、`7/2`，拒绝 `31/2`、`3 1/2`。`tools/test-spr.cjs` 的 42 条断言与这张表逐条吻合，实跑全过。
2. **官方配速正确**：R&W 64 分钟 / 54 题 ≈ 71 秒，Math 70 分钟 / 44 题 ≈ 95 秒（`index.html:1487`、`2180`、`2186`）。
3. **Desmos 用的是官方考试构建**：`https://www.desmos.com/testing/cb-sat-ap/graphing`（`index.html:695`），与 College Board 给 SAT/AP 的版本一致。
4. **题库数据与官方 API 抽样一致**：随机抽 12 题对拍 `get-question`，题干/选项/答案/解析的文本内容一致；差异仅在 `mfenced` → `mrow` 的 MathML 归一化（渲染需要，不改变内容）。
5. **题库结构健康**：3,311 题、无重复 id；2,917 道 MCQ 全部 4 个选项、答案均为单个 A–D；394 道 SPR 答案键格式合理（含分数/小数/负数/多解）。
6. **做题时不泄露答案/解析**：即时解析层被隐藏（`index.html:2500-2501`），解析集中在交卷后的复盘页；这符合“练习不偷看”的目标。
7. **官方工具里已实现的**：Mark for Review、Option Eliminator（X 排除）、Question Menu、原文划词高亮。**程序自己的功能**（非官方工具）：收生词、错题本、复盘导出。

## 5. 存疑项（无法用现有材料确认，标注出来）

1. **“错因自动归类覆盖率英语 59%、数学 7%”**（README:55）：仓库里没有生成这两个数字的脚本或数据。用全量干扰项穷举（每题 3 个错项、`ms=0`）实测得到：英语 2,137/5,535 ≈ **38.6%**，数学 137/3,216 ≈ **4.3%**。口径可能不同（实际用户只选一个错项，且 59% 可能是按用户作答统计），所以**不能判定 README 造假**，但这两个数字目前不可复现。
2. **“3,311 道 College Board 官方真题”**：数据源是 SAT Suite Educator Question Bank（官方题池/练习题），不是官方放出的历年真题卷。称“真题”不准确，建议改成“官方题库题”。
3. **“两阶段自适应路由”**：README 的“已知缺口”已承认难度自适应没做；但模考页仍在承诺（见 F1）。这不是能力问题，是文案与实现不一致。
